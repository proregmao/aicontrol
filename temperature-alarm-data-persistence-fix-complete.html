🔧 核心问题分析与修复

1. 问题根本原因

  • 数据库表结构冲突：原有的 alarm_rules 表结构与温度告警规则不匹配
  • 模拟数据返回：API方法只返回模拟数据，没有实际保存到数据库
  • 前端显示硬编码：实时监控的警告范围是硬编码的，没有与告警规则关联

2. 完整修复方案

  • 创建专用数据表：新建 temperature_alarm_rules 表，专门存储温度告警规则
  • 实现真实CRUD：所有API方法都连接数据库，实现真实的增删改查操作
  • 动态数据关联：前端实时监控卡片从告警规则动态获取警告范围
  • 数据同步更新：修改告警规则后，实时监控显示立即更新

🗄️ 数据库结构设计

新建表：temperature_alarm_rules

CREATE TABLE temperature_alarm_rules ( id SERIAL PRIMARY KEY, probe VARCHAR(50) NOT NULL, -- 探头名称 location VARCHAR(100) NOT NULL, -- 位置描述 normal_range VARCHAR(50) NOT NULL, -- 正常范围 warning_threshold VARCHAR(50) NOT NULL, -- 警告阈值 danger_threshold VARCHAR(50) NOT NULL, -- 危险阈值 status VARCHAR(20) DEFAULT '正常', -- 当前状态 enabled BOOLEAN DEFAULT true, -- 是否启用 created_at TIMESTAMP DEFAULT NOW(), -- 创建时间 updated_at TIMESTAMP DEFAULT NOW() -- 更新时间 );
