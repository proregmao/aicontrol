🔍 问题根本原因分析

数据库查询无排序

核心问题：数据库查询没有指定ORDER BY子句，导致每次返回的记录顺序可能不同

// 问题代码 (后端) var alarmRules []TemperatureAlarmRule err := db.Find(&alarmRules).Error // ^^^^ 没有指定排序，数据库可能按任意顺序返回记录 // 结果：每次查询可能得到不同的顺序 第1次查询：[探头2, 探头1, 探头4, 探头3] 第2次查询：[探头1, 探头3, 探头2, 探头4] 第3次查询：[探头4, 探头1, 探头3, 探头2]

数据库行为说明

  • 无ORDER BY查询：数据库不保证返回顺序的一致性
  • 物理存储影响：可能按插入顺序、索引顺序或其他内部顺序返回
  • 并发操作影响：增删改操作可能影响下次查询的返回顺序
  • 数据库优化：查询优化器可能选择不同的执行计划

用户体验影响

  • ❌ 视觉混乱：用户每次刷新看到不同的顺序
  • ❌ 操作困难：难以找到特定的告警规则
  • ❌ 信任度下降：用户怀疑系统稳定性
  • ❌ 编辑错误：可能编辑错误的规则

🔧 完整修复方案

1. 添加数据库排序

// 修复后：按ID升序排序 var alarmRules []TemperatureAlarmRule err := db.Order("id ASC").Find(&alarmRules).Error // ^^^^^^^^^^^^^^ 添加排序子句，确保每次查询顺序一致

2. 排序策略选择

选择按ID升序排序的原因：

  • ✅ 稳定性：ID是主键，唯一且不变
  • ✅ 逻辑性：通常按创建时间顺序排列
  • ✅ 性能：主键索引，查询效率高
  • ✅ 一致性：所有环境下都保持相同顺序

3. 其他可选排序方案

// 方案1：按探头名称排序 db.Order("probe ASC").Find(&alarmRules) // 方案2：按创建时间排序 db.Order("created_at ASC").Find(&alarmRules) // 方案3：按位置排序 db.Order("location ASC").Find(&alarmRules) // 方案4：多字段排序 db.Order("probe ASC, id ASC").Find(&alarmRules)

4. 完整修复代码

// GetAlarmRules - 获取所有告警规则（按ID升序排序） func GetAlarmRules(ctx *gin.Context) { db := database.GetDB() if db == nil { ctx.JSON(http.StatusInternalServerError, models.APIResponse{ Code: http.StatusInternalServerError, Message: "数据库连接失败", }) return } var alarmRules []TemperatureAlarmRule err := db.Order("id ASC").Find(&alarmRules).Error // 关键修复 if err != nil { ctx.JSON(http.StatusInternalServerError, models.APIResponse{ Code: http.StatusInternalServerError, Message: "获取告警规则失败", }) return } // 初始化默认数据（如果为空） if len(alarmRules) == 0 { initDefaultAlarmRules(db) err = db.Order("id ASC").Find(&alarmRules).Error // 重新查询，保持排序 } ctx.JSON(http.StatusOK, models.APIResponse{ Code: http.StatusOK, Message: "获取告警规则成功", Data: alarmRules, }) }
