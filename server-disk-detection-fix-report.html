🚨 发现的问题

原始问题描述

用户反映服务器管理中的磁盘信息检测有问题，显示的磁盘信息不正确。

用户看到的磁盘信息：

设备 挂载点 文件系统 总容量 已用 使用率
/dev/sda1 / ext4 3.64 TB 1.09 TB 30%
/dev/nvme0n1 /home ext4 232.89 GB 46.57 GB 20%

根本原因分析

  • 硬编码数据：getDiskInfoViaSSH函数返回固定的模拟数据
  • 未执行真实命令：虽然注释说要执行df命令，但实际没有执行
  • 数据不准确：显示的磁盘信息与实际服务器不符

🔧 修复实现

1. 核心修复内容

❌ 修复前（硬编码）

// 模拟真实的磁盘信息 disks := []models.DiskInfo{ { Device: "/dev/sda1", Mountpoint: "/", Fstype: "ext4", Total: 4000787030016, // 硬编码 Used: 1200000000000, // 硬编码 Usage: 30.0, // 硬编码 }, } return disks, nil

✅ 修复后（真实SSH命令）

// 创建SSH连接 conn, err := s.createSSHConnection(req.IPAddress, req.Port, req.Username, req.Password, req.PrivateKey) if err != nil { return nil, fmt.Errorf("创建SSH连接失败: %w", err) } defer conn.Close() // 执行 df -h 命令获取磁盘使用情况 session, err := conn.NewSession() if err != nil { return nil, fmt.Errorf("创建SSH会话失败: %w", err) } defer session.Close() // 执行命令获取磁盘信息 output, err := session.CombinedOutput("df -h --output=source,target,fstype,size,used,pcent | grep -E '^/dev/'")

2. 新增功能特性

  • 大小转换：新增parseDiskSize函数，支持K/M/G/T/P单位转换
  • 错误处理：完善的错误处理和默认值机制
  • 数据验证：验证解析结果的完整性

3. 磁盘大小解析函数

// parseDiskSize 解析磁盘大小字符串，返回字节数 func (s *ServerService) parseDiskSize(sizeStr string) uint64 { // 支持 K/KB, M/MB, G/GB, T/TB, P/PB 单位 switch unit { case "K", "KB": return uint64(size * 1024) case "M", "MB": return uint64(size * 1024 * 1024) case "G", "GB": return uint64(size * 1024 * 1024 * 1024) case "T", "TB": return uint64(size * 1024 * 1024 * 1024 * 1024) case "P", "PB": return uint64(size * 1024 * 1024 * 1024 * 1024 * 1024) } }
