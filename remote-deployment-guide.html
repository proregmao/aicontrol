🚀 智能设备管理系统远程部署指南

一键部署到 192.168.110.21 服务器

后端端口: 2999 | 前端端口: 3000

📋部署概述

本指南将帮助您将智能设备管理系统完整部署到远程服务器 192.168.110.21。

配置项 值 说明
目标服务器 192.168.110.21 远程部署服务器
后端端口 2999 Go后端API服务端口
前端端口 3000 Vue前端Web服务端口
部署目录 /opt/smart-device-management 服务器上的安装目录
Web服务器 Nginx 前端静态文件服务和反向代理
进程管理 systemd 后端服务进程管理

⚠️部署前准备

本地环境要求

  • ✅ Node.js >= 18.0.0
  • ✅ Go >= 1.23.0
  • ✅ SSH客户端
  • ✅ 网络连接到目标服务器

远程服务器要求

  • ✅ Ubuntu/Debian Linux系统
  • ✅ Root权限或sudo权限
  • ✅ PostgreSQL数据库 (192.168.110.21:5432)
  • ✅ Redis缓存 (192.168.110.21:6379)
  • ✅ 端口2999和3000可用

⚠️ 重要提醒

  • 确保SSH密钥已配置或知道root密码
  • 确保PostgreSQL和Redis服务正在运行
  • 确保防火墙允许2999和3000端口访问

🚀一键部署

使用我们提供的自动化部署脚本，只需一条命令即可完成整个部署过程：

./scripts/remote-deploy.sh deploy

这个命令将自动执行以下步骤：

  1. 检查本地依赖环境
  2. 构建前端Vue应用
  3. 构建后端Go应用
  4. 创建部署包
  5. 上传到远程服务器
  6. 在远程服务器上安装和配置
  7. 启动服务并检查状态

🔧分步部署（可选）

如果您希望分步执行部署过程，可以使用以下命令：

1. 构建应用

# 只构建前端和后端，不部署 ./scripts/remote-deploy.sh build

2. 创建部署包

# 构建并创建部署包 ./scripts/remote-deploy.sh package

3. 检查服务状态

# 检查远程服务器上的服务状态 ./scripts/remote-deploy.sh status

⚙️部署过程详解

环境检查

检查本地Node.js、Go和SSH环境是否就绪

前端构建

执行 npm install 和 npm run build，生成生产版本的静态文件

后端构建

使用Go交叉编译，生成Linux x64架构的二进制文件

配置文件生成

自动生成生产环境的.env配置、Nginx配置和systemd服务文件

部署包创建

将所有文件打包成tar.gz格式的部署包

远程上传

通过SCP将部署包上传到目标服务器

远程安装

在远程服务器上解压、安装依赖、配置服务

服务启动

启动Nginx和后端服务，并设置开机自启

健康检查

验证服务是否正常运行，端口是否正常监听

✅部署后验证

访问地址

  • 前端应用: http://192.168.110.21:3000
  • 后端API: http://192.168.110.21:2999
  • 健康检查: http://192.168.110.21:2999/health

服务状态检查

# 检查后端服务状态 systemctl status smart-device-backend # 检查Nginx状态 systemctl status nginx # 检查端口监听 netstat -tlnp | grep -E ":2999|:3000"

日志查看

# 查看后端服务日志 journalctl -u smart-device-backend -f # 查看Nginx日志 tail -f /var/log/nginx/access.log tail -f /var/log/nginx/error.log

🔧故障排除

常见问题

1. SSH连接失败

# 测试SSH连接 ssh root@192.168.110.21 # 如果需要密码认证，确保知道root密码 # 或者配置SSH密钥认证

2. 端口被占用

# 检查端口占用 netstat -tlnp | grep -E ":2999|:3000" # 停止占用端口的进程 sudo kill -9 [PID]

3. 数据库连接失败

# 检查PostgreSQL服务 systemctl status postgresql # 测试数据库连接 psql -h 192.168.110.21 -U postgres -d smart_device_management

4. 服务启动失败

# 查看详细错误日志 journalctl -u smart-device-backend -n 50 # 手动启动测试 cd /opt/smart-device-management/backend ./smart-device-management
